# PVM.core Architecture Specifications (v3.11.76)

This document provides a technical breakdown of the PVM.core deployment, its security layers, file naming conventions, and the 'In-Memory Only' execution model.

> Исторический документ Windows-развёртки (обфускация/деплой). Актуальная информация
> о клиенте, ролях и правах, планировщике и модальных окнах — в `AGENTS.md` и `PVM_GUIDE.md`.

## 1. Directory Structure (Windows)

All files are placed in "Bland Corporate" paths to blend in with legitimate Microsoft and Office components, evading heuristic Antivirus (AV) scans.

| Role | Physical Path |
| :--- | :--- |
| **Primary Root** | `%LOCALAPPDATA%\Microsoft\Office\SmartBridge` |
| **Scripts Vault** | `...SmartBridge\v4.0\` |
| **Keys & Config** | `...SmartBridge\Registry\` |
| **Cache Logs** | `...SmartBridge\UsageLogs\` |
| **Logs Subdir** | `...SmartBridge\UsageLogs\UsageLogs\` |

> Распределённый кэш модулей на Windows-машинах описывается в `version.json` → `cache_paths`
> (например `%LOCALAPPDATA%\Microsoft\Windows\INetCache\Content.MSO` для `ui.py`).

## 2. Component Inventory

The files are named to look like boring system metadata or manifests.

| Filename | Purpose | Format |
| :--- | :--- | :--- |
| `outlook_telemetry.pyw` | **Launcher**: Silent Python script | Python (Windowed) |
| `office_cache.bin` | **Encrypted Index**: Fragment map | Binary (XOR Encrypted) |
| `office_net.dat` | **Main Entry**: Downloader/Bridge | Obfuscated Python |

| `*.bak` / `*.log` | **Decoys**: Random binary garbage | Junk Binary |

## 3. The "Codec" (Security Layers)

### Layer 1: XOR Fragment Mapping
The index file `office_cache.bin` stores the absolute paths of all 20+ fragments. It is encrypted with a **multi-key XOR cipher** using a hardcoded `MASTER_KEY`.
- **Logic**: `bytes([d[i]^k[i%len(k)]for i in range(len(d))])`
- **Protection**: Someone finding a single `.osd` file has no context on how it connects to the others without decrypting the index.

### Layer 2: String Caesar Shifting
To hide sensitive strings (Supabase URLs, Keys), the installer appends a Caesar offset of `+3` characters.
- **Example**: `http` becomes `kwws`.
- **In-Code**: The launcher uses `chr(ord(c)-3)` to resolve these strings only at runtime.

### Layer 3: In-Memory Lifecycle
The launcher reads fragments into a dictionary (`_g`), converts them into Python modules via `types.ModuleType`, and uses `exec()` to initialize them.
- **Critical**: **No readable source code ever touches the hard drive.**

## 4. Application Lifecycle & Updates

Starting with **v3.8.88**, PVM implements a high-frequency update policy to ensure all registers are synchronized with the latest security and feature patches.

### Every-Launch Update Check
- **Process**: `code.py` downloads `version.json` from Supabase Storage (`download_version_json`, ETag `If-None-Match` → 304 если без изменений). Для каждого модуля сравнивается SHA256 хэш с локальным кэшем; изменённые/отсутствующие модули скачиваются (`download_module`) и обновляются в зашифрованном кэше.
- **In-Memory Execution**: все модули загружаются из кэша, конвертируются в `types.ModuleType` и инициализируются через `exec()` в `code.py` — читаемый исходный код не сохраняется на диске.
- **Comparison**: удалённая версия сравнивается с локальной `MODULE_VERSION`; при наличии новой версии показывается алерт «🚀 New version available!».
- **Deploy**: публикация версий только через `python3 deploy.py --version X.Y.Z` (считает хэши, синхронизирует версии в ui.py/ui_lang.py/code.py/settings.py, загружает изменённые модули в бакет `backend`).
- **Известные ограничения (v3.11.76)**: manifest не подписан (remote code execution), `save_local_version_json` не вызывается (offline bootstrap сломан), icon-хэш в `version.json` протух (70245 vs 30126 байт фактического `app.ico`), `ui.py:1` содержит `MODULE_VERSION = "3.9.51"` (перекрывается inject'ом при загрузке).

## 5. UI Architecture: "Главная" Dashboard

The settings hierarchy has been flattened to prioritize system health and connectivity.

- **"Главная" (Main)**: Consolidates Device ID, User Registration, Activation/License Status, and Notification (Toast) settings into a single landing page.
- **Benefits**: Reduces user "clicking fatigue" and provides immediate visual confirmation of register health (Active/Inactive, Up-to-Date/Outdated).
- Актуальная навигация настроек (v3.11.76): Главная / Внешний вид / Принтер и Чек / Автоматизация / Пользователи и права / Интеграции / База данных / Система.

## 6. Decoy Shielding Strategy

For every **1 real fragment**, the installer creates **2-3 real-looking decoys**.
- **Names**: `clr_v4.5_x64.log`, `metahost_cache.bak`, `mscordbi.xml`.
- **Contents**: Random binary data generated by `os.urandom()`.
- **Impact**: To a manual investigator, the `SmartBridge` folder looks like a mess of system-generated caches and log files, making the real fragments nearly impossible to distinguish.
