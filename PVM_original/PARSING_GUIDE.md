# Парсинг товаров в наличии (Автоскладирование)

Документ описывает, как приложение PVM.core собирает каталог товаров поставщика
GreenLeaf (greenleaf-global.com), включая остатки «в наличии», и синхронизирует его
с локальной базой данных.

Реализация: **`ui_autoreview.py`** — вкладка **«Автоскладирование»** (Autoreview).
Краткое описание фичи: `ТЗ PVM original.md` § 9.7 (строки 581–584).

---

## 1. Что делает функция

- Входит в кабинет поставщика GreenLeaf через **Playwright** (headless Chromium).
- Открывает раздел покупки товаров (`#admin/shop/buy` — «Новая продажа»).
- Проходит по каталогу страницами (кнопка «Показать еще...», до 200 страниц).
- Для каждой позиции извлекает: код, название, **количество в наличии**, цену, PV.
- Синхронизирует данные с локальной таблицей `goods` (создание/обновление).

Лог работы: «Каталог получен: N позиций» → «Синхронизация завершена: создано X,
обновлено Y, пропущено Z».

## 2. Основные шаги алгоритма

> Номера строк приведены по v3.11.76 — при работе сверяйте с `grep -n "def _ar_..." ui_autoreview.py`.

| Шаг | Где в коде | Что происходит |
|---|---|---|
| 1. Подготовка | `_ar_run` (ui_autoreview.py:659) | Запуск сессии, проверка Playwright-браузеров |
| 2. Вход в кабинет | `_ar_login` (:776) | `https://greenleaf-global.com/office/login?goto=%2Fdashboard`, логин/пароль из настроек приложения или из Supabase по device key |
| 3. Навигация | `_ar_scrape_goods` (:908) | Переход в `a[href="#admin/shop/buy"]`, запасной вариант «Новая продажа» или прямой URL `https://greenleaf-global.com/do.vshow#admin/shop/buy` |
| 4. Вход в раздел покупки | `_ar_enter_partner` (:877) | Заполнение `input[check_query="login_buy"]` логином **`kz44326234`** (захардкожен), кнопка «Далее» |
| 5. Получение каталога | `_ar_scrape_goods` (:908+) | Ожидание строк каталога, до 3 попыток (перезагрузка страницы) |
| 6. Сбор позиций | `_ar_scrape_goods` | Перебор строк `tr.goods-item` / `tr.good_item` (`_ar_find_goods_rows`, :851), нажатие «Показать еще...» |
| 7. Разбор строки | `_ar_parse_row` (:1032) | Извлечение полей из HTML (см. § 3) |
| 8. Применение в БД | `_ar_apply_changes` (:1091) | Создание/обновление товаров в `goods` |
| 9. Очистка названий | `_ar_auto_clean_names` (:1188) | Чистка всех названий в БД через `clean_product_name` |

Остановка в любой момент: кнопка «Приостановить» / флажок `_ar_stop_event` —
выбрасывает `InterruptedError("stopped")`, прерывающий все циклы.

## 3. Какие поля парсятся (`_ar_parse_row`, ui_autoreview.py:1032–1090)

Строка каталога разбивается на ячейки `<td>` (нужно не менее 6).

| Поле | Источник | Обработка |
|---|---|---|
| **Код товара** | Ячейка 0, текст после `<br>` | Строгий формат `^[A-Z]{3}\d{3}$` (`PRODUCT_CODE_STRICT_RE`, :22) — например `ABC123`. Если код не подходит — позиция **пропускается** (`skipped=True`, :1042–1046) |
| **Название** | Ячейка 1, `div.data-title` | Чистка через `clean_product_name` (:35): удаляет `&nbsp;`, лишние пробелы, приставку «Кол-во в коробке: N шт.», суффиксы «Доступно для продажи: N» и «Доступно: N» |
| **Количество в наличии** | Ячейка 1, текст | Regex `Доступно для продажи:\s*(\d+)` (`AVAILABLE_QTY_RE`, :30) → сохраняется в поле `quantity`. Если текст не найден — `0` |
| **Цена продажи** | Ячейка 3, первое число в `<b>` | `sale_price = discount_price * 2` (цена на сайте — скидочная, умножение на 2) (:1072) |
| **PV** | Ячейка 4 | Число с плавающей точкой |
| **Штрихкод** | — | Всегда пусто |

> Цены целые: `sale_price` округляется до целого при записи в `GoodsManagerSQL.add_good`
> (единая нормализация цен в db_sqlite.py — копеек в БД нет).

## 4. Режимы работы

При первом запуске режим **обновляющий**: существующие товары перезаписываются,
если изменились название, цена, PV или количество (`need_update`).

При повторном запуске показывается диалог (`_ar_confirm_rerun`, :524):

- **По умолчанию — «только новые товары»** (`add_only=True`): существующие товары
  не изменяются, пропускаются («Режим: только новые товары»).
- Чекбокс «Обновить кол-ва товаров (нежелательно!)» → `add_only=False`:
  обновление как при первом запуске.

Статистика применения (:1089–1184):
- создано новых товаров (`new_codes`),
- обновлено (`updated_codes`),
- изменение количества: увеличение/уменьшение (`qty_increased` / `qty_decreased`),
- изменение цены (`price_changed`),
- без изменений (`unchanged`).

Создание/обновление выполняется через `goods_manager.add_good(...)` с
`set_quantity=True` и `user_name="Autoreview"` (видно в истории изменений).

## 5. Ограничения и особенности

- Работает только при наличии интернета и доступа к greenleaf-global.com.
- Логин партнёра для раздела покупки **`kz44326234` зашит в код** (`_ar_enter_partner`).
- Учётные данные кабинета берутся из полей логина приложения или из Supabase
  (`db.get_credentials_from_supabase`) — если нет, ошибка «Учетные данные не настроены».
- Каталог собирается до 200 страниц («Показать еще...»).
- Коды не формата `ABC123` (например, длинные SKU) пропускаются и попадают в
  статистику «Пропущено позиций».
- Примечание: `SKIP_CODE_PATTERN` (`^[A-Z]{1,2}\d{3,}$`, :32) определён в коде,
  но в текущей версии не используется — фильтрация происходит только по
  `PRODUCT_CODE_STRICT_RE`.
- Цена продажи = скидочная цена × 2, округляется до целого в `add_good` —
  проверяйте соответствие реальной наценке.
- Одновременный запуск с PV-ботом запрещён (`_ar_start`, :566).
- Ошибки сети: 3 попытки получения каталога с перезагрузкой, затем
  «Не удалось получить каталог поставщика».

## 6. Быстрая проверка после запуска

1. Во вкладке «Автоскладирование» нажмите **«Запустить автоскладирование»**.
2. Ожидайте в логе: вход выполнен → «Каталог получен: N позиций» → «Синхронизация
   завершена: создано X, обновлено Y, пропущено Z».
3. Сверьте пару кодов из каталога с количеством «Доступно для продажи: N» на сайте
   и полем `quantity` в таблице товаров (вкладка «Товары»).
