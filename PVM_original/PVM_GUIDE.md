# PVM.core — Partner-Vending Matrix System

Текущая версия: **v3.11.76** (см. `version.json`). Подробная справка для агента — `AGENTS.md`.

## Архитектура

PVM.core — десктопное приложение для автоматизации розничных продаж и партнёрских программ. Построено на **Python 3** с графическим интерфейсом **Tkinter**, локальной базой данных **SQLite**, лицензированием через **Supabase** и файловой синхронизацией между кассами через общую папку **MEGA**.

### Ключевые компоненты

- **Интерфейс**: Tkinter (`tk.Frame`, `ttk.Notebook`, `Canvas` + `Scrollbar`)
- **База**: SQLite через единый `DatabaseManager` и предметные менеджеры (`ReceiptsManagerSQL`, `PartnersManagerSQL`, `GoodsManagerSQL`)
- **Облако**: Supabase REST API для лицензий, тарифов и уведомлений
- **Синхронизация**: общая папка MEGA (файлы JSONL через `sync_engine` + `sync_queue`)
- **Боты**: Playwright-автоматизация для GreenLeaf (PV Bot + Autoreview)

## Текущее состояние (v3.11.76)

### Роли и права
- Роли: `superadmin` (единственный, первый созданный; несменяем, неудаляем), `admin`, `cashier`, `viewer`.
- Миграция `ensure_superadmin()`: старейший активный `admin` повышается, если суперадмина нет.
- Панель прав: Настройки → Пользователи и права → «Права доступа». Категории в `PERM_CATEGORIES` (ui.py),
  «Настройки» — в самом низу. Суперадмин в шаблонах ролей не предлагается.
- PV Бот: вкладка видна всем при подписке 3/4; ручной запуск гейтится правом `pvbot_use`;
  автозапуск планировщика правами НЕ гейтится. «Статистика» гейтится `analytics_view`.

### Планировщик
- Один запуск в день — **in-memory** (`last_run_date` + `initial_check` в `scheduler_loop`).
  Persistent-файл `cache/pvbot_last_run.json` НЕ используется (сирота от старых версий).
- Поколения: `_scheduler_generation` (рестарт) и `_scheduler_config_generation` (смена
  времени/папки сбрасывает маркер дня).
- Старт отложен на 5с после mainloop; поток не трогает Tk напрямую (`_tk_after`, кэши);
  стоп по `_stop_events['scheduler']`.

### Shutdown-координатор (C3)
- `_stop_events` (ui.py): scheduler / autoreview / live_bot / integration / sync.
- `_stop_all_workers()`: все стоп-ивенты + join ≤3с + `_cancel_pending_afters()`.
- Sync-циклы — отслеживаемые потоки (`_run_sync_cycle`); `SyncEngine.stop()` выводит
  in-flight цикл между стадиями.
- Exit-report выполняется после остановки воркеров и джойнится (10с).

### Атомарные операции
- `InventoryOpsManagerSQL` — единая транзакционная точка sale/purchase/refund/writeoff
  (чек + остатки + партнёр, `_check_stock`, rollback). Вызовы из ui_pos/ui_arrival/ui_sales.

### Синхронизация (протокол v2, дельты)
- MEGA-фолдер — единственный путь синка; JSONL outbox с манифестом+checksum;
  `sync_inbox` с `event_id` (INSERT OR IGNORE); tombstones; LWW по `updated_at`
  (только каталог-поля); 7 сущностей (goods, stock_delta, partners, receipts,
  purchases, writeoffs, audits).
- Остатки — аддитивные дельты (`trg_goods_stock_delta`): приход/продажа/списание/
  возврат/ревизия/автоскладирование на любом устройстве сходятся без «мастера».
- Ребаза: первый goods-снапшот кассы выставляет абсолютные остатки (маркеры
  `stock_rebase_v2`/`stock_rebase_cutoff`); «Полная пересинхронизация» — повтор при ошибке.
- Снапшоты (еженедельно, keep=2 на сущность): goods, partners, receipts,
  purchases, writeoffs, audits — восстановление после офлайна >35 дней.
- Janitor: outbox 35 дней (только свои файлы при отсутствии других устройств;
  ack всех живых + нет pending-событий); реестр устройств протухает за 60 дней.
- ID приходов/списаний: `{device_key[:4]}-{counter}` (без коллизий устройств).

### OTP
- `OTPManager`: генерация `secrets.randbelow`, привязка к пользователю, TTL 10 мин,
  лимит 5 попыток. Успешный OTP = вход (recovery-фактор; PIN повторно не проверяется).

### Прочее
- Модальные окна: статичные (`transient` + `grab_set` + `lift()`, `-topmost` НЕ используется),
  `dismiss_on_outside` для просмотров, insist для форм/подтверждений.
- Цены — только целые (`int(round())` в `add_good`, валидация «только цифры» в полях).
- Единый поиск: `_current_search_input()` + `_focus_search_field()`.
- Чистая остановка бота: stop-aware `_wait_visible`, без playwright-вызовов с главного потока.
- Смена пользователя: кнопка в Настройках → Главная и пункт трея; цикл сессий в `code.py`.
- Toast-настройки хранятся в `appearance_settings` и сохраняются туда же (`save_all_settings`).

## Порядок деплоя

```bash
# Из корня проекта:
python3 deploy.py --version X.Y.Z
```

Скрипт:
1. Обновляет версию во всех исходных файлах
2. Вычисляет SHA256 хэши изменённых файлов
3. Сравнивает с предыдущей версией на Supabase
4. Загружает только изменённые модули
5. Обновляет `version.json`

## Инструкции для ИИ-агента

При старте новой сессии первым делом читать `PVM_GUIDE.md` и `AGENTS.md`. Основные принципы:

- **Не добавлять новые зависимости** без явного запроса пользователя
- **Не ломать обратную совместимость** БД (миграции только через ALTER TABLE)
- **Перед редактированием** читать контекст файла (минимум 50 строк вокруг изменяемого места)
- **После изменений** проверять синтаксис: `python3 -c "import py_compile; py_compile.compile('file.py', doraise=True)"`
- **Деплой** только через `python3 deploy.py --version X.Y.Z`

### v3.11.43 — Чек: убран «?» в обрезанных наименованиях
- 🔴 Причина: длинные названия обрезаются с многоточием «…» (U+2026), а в CP866 (печать) такого символа нет → печатался «?».
